# 实时字幕两遍识别:流式首遍探针 + 落地验证(2026-11-28)

## 方案

- **假设**:sherpa-onnx 流式 zipformer 双语 zh-en(int8)当首遍出 partial,现有 SenseVoice Small INT8 当二遍出终稿,可在零新增 pip 依赖下复刻飞书「边录边改前面文字」的两遍识别体验。
- **基线**:SenseVoice + silero VAD 分段伪流式(v0.11.0),只有整句 final。
- **数据**:`say -v Tingting -r 210` 合成 26.5s 中文口播(3 句句号分段),afconvert 转 16k mono;`data/probe_zh_16k.wav` 随目录留档。
- **超参/口径**:OnlineRecognizer.from_transducer(num_threads=2, greedy, endpoint off),100ms 块喂入;CER=字级编辑距离/参考长(双方去标点空白);流式模型 `csukuangfj/sherpa-onnx-streaming-zipformer-bilingual-zh-en-2023-02-20` int8(~190MB,hf-mirror 拉取,落 `~/.earshot/models/asr_stream/`)。
- **评测口径**:验收=「粗稿可糙,终稿必须对」——粗稿只看延迟与可读性;终稿必须与无粗稿基线逐字一致。

## 结果

- **粗稿延迟**:partial 与语音同步滚动(说到的词百 ms 级上屏);26.5s 音频流式侧解码总耗时 **0.65s ≈ 40 倍实时**,CPU 无压力。
- **粗稿质量**:末次 partial 对 SenseVoice 终稿 **CER 2.4%**;错误全为同音字级(得→的/自→字/IP→而B),无标点——粗稿该有的样子,全部由二遍纠正。
- **落地代码**(commit 见 `feat: 实时字幕两遍识别`):
  - `models.py`:STREAM_MODEL_FILES 与核心 MODEL_FILES 分离,**只有 listen 路线** `ensure_models(include_stream=True)` 下载 190MB,批量路线零增量;doctor 增体检项。
  - `transcribe.py`:`PartialFeed`(流式供给器,`reset()` 段闭合重开流)+ `run_live(partial_feed, on_partial)` 每窗挂载点 + `LocalTranscriber._new_partial_feed()`(模型缺失返 None 降级为仅终稿)。
  - `live.py`:LiveSession 增 `on_partial` 通道;`cli.py`:listen 渲染状态机——粗稿行原行刷新(`\r\033[K`+end=""),终稿换行定格,电平 meter 在字幕行亮着时让路(cap_lock 串行化双线程打印)。
- **端到端**(verify_live.py,真引擎 listen 同路径):粗稿事件 67 个、粗稿流重置 3 次=段数 3(10s 滚动预算兜底生效);终稿与「无粗稿件基线」逐字一致。
- **质量门**:ruff ✓ / mypy strict ✓ / pytest 128 ✓(新增 6:partial 逐窗喂+逐段重置/段内去重/双通道顺序/无粗稿降级/模型清单分离×2);`earshot audio` 批量回归 ✓。

## 思考

- **粗稿流重置时机是关键设计**:reset 挂在 drain(段闭合)上,粗稿行不背上一句尾巴;10s 滚动预算兜底保证连续口播下粗稿行也不会无限增长。
- **终稿分段差异不是回归**:live(10s 预算)与批量(55s)的 VAD 切分边界不同,live 强制闭段可能落在句中(「…判断一个人是。/不是网红的标准…」)——v0.11 既有行为,合成语音连读时更明显;真人说话停顿多,自然闭段占主导。
- **电平 meter 与粗稿行同一行**:靠 cap_open 状态互斥(字幕亮着 meter 让路,终稿定格后恢复),比「meter 永久隐藏」保留了静音期的采集活性信号。
- sherpa-onnx 流式 API(`is_ready`/`decode_stream`/`get_result`)与离线同仓零新依赖,验证了「同栈拼 2pass」路线成立。
