# 实时字幕两遍识别(2pass)方案

> 2026-11-28 落地(main 1c2f24e,v0.12.0 发版)。本文是方案的单一事实源:后续迭代(换模型/调节流/加能力)先读这里,别从代码反推设计。

## 背景与目标

飞书录音的体验:边录边出字,且**前面已出的文字会被改写**——这是流式 ASR 的「两遍识别」(2-pass decoding):首遍流式模型分块出临时粗稿(partial,快但糙),VAD 闭段后整句音频交更大模型重识别出终稿(final,准),终稿回写替换粗稿。粗稿负责快,终稿负责对。

earshot 原状是「分段伪流式」:SenseVoice + silero VAD,每段闭段后整段解码一次,只有 final 没有 partial——不糊但也不滚,要等停顿才见字。

**验收口径(用户拍板)**:「粗稿可糙,终稿必须对」。终稿路径必须零改动。

## 选型结论

| 方案 | 结论 | 一句话理由 |
|---|---|---|
| **A. sherpa-onnx 流式模型当首遍 + 现有 SenseVoice 当二遍** | ✅ 采用 | 零新增 pip 依赖,二遍模型白拿,保持端侧/零成本/轻量 |
| B. FunASR 官方 2pass 全家桶 | ❌ | 引入 torch(~2GB)与轻量栈冲突,等于维护两套语音栈 |
| C. 云端流式 API(火山/讯飞等) | ❌ | 破坏端侧定位;旁听录音上云有隐私问题;断网/计费失效 |
| D. faster-whisper + commit-when-stable | ❌ | CPU 每秒重算整缓冲;中文精度低;语种已钉 zh,多语种非诉求 |

## 架构

```
录音流(16k) ──每窗512样本──> silero VAD ──闭段──> SenseVoice 整段解码 ──> 终稿(带标点,回写定格)
     │
     └────────每窗同步喂──> 流式 zipformer(粗稿) ──变化即回调──> 粗稿行(原行刷新)
```

组件与落点:

| 组件 | 文件 | 职责 |
|---|---|---|
| `STREAM_MODEL_FILES` / `missing_stream_models` | `models.py` | 粗稿模型清单(与核心 MODEL_FILES 分离);`ensure_models(include_stream=True)` 仅 listen 路线传 |
| `PartialFeed` | `transcribe.py` | 流式首遍供给器:`__call__(window)->str` 逐窗增量解码;`reset()` 重开流 |
| `PartialFeeder` | `transcribe.py` | Protocol(run_live 与单测假件的结构契约) |
| `run_live(partial_feed, on_partial)` | `transcribe.py` | 每窗挂载点:`accept → drain(闭段即 reset) → partial_feed → 去重后 on_partial`;粗稿/终稿必须同给才启用 |
| `LiveSession(on_text, on_partial)` | `live.py` | 双通道线程封装;transcriber 无 `_new_partial_feed` 时自动降级仅终稿 |
| 渲染状态机 | `cli.py` cmd_listen | `_show_partial`(粗稿原行刷新)/`_show`(终稿换行定格)/`_meter`(cap_open 互斥);cap_lock 串行化双线程打印 |

模型:`csukuangfj/sherpa-onnx-streaming-zipformer-bilingual-zh-en-2023-02-20` int8(~190MB,encoder 173MB),落 `~/.earshot/models/asr_stream/`,hf-mirror 自动下载;`LocalTranscriber._new_partial_feed()` 发现缺文件返回 None → 降级为仅终稿,批量/云引擎路线完全不受影响。

## 关键设计决策

1. **reset 挂在 drain(段闭合)上**:粗稿流随 VAD 闭段重置,不背上一句尾巴;10s 滚动预算(`LIVE_CAPTION_MAX_RUN_S`)兜底保证连续口播下粗稿行也不会无限增长。
2. **粗稿去重**:`last_partial` 只在内容变化时上屏(段内去重;reset 后清空,新段必首报)。
3. **终稿零改动是硬约束**:粗稿挂载点在 VAD 喂入之后、终稿解码之前,对拍基线 = **同预算、无粗稿件**的 run_live,逐字一致才放行(见 `experiments/20261128-streaming-firstpass-probe/verify_live.py`)。
4. **电平 meter 让路**:字幕行亮着(cap_open)时 meter 停印,终稿定格后自动恢复——保住静音期的采集活性信号,又不会踩字幕行。
5. **endpoint 检测关闭**:闭段由 silero VAD 单一驱动,粗稿流不做自己的断句,两遍共享同一套切分事实。

## 已知边界(别当 bug 修)

- 粗稿无标点、含同音字错(CER ~2.4%):设计如此,终稿全纠。
- live(10s 滚动预算)与批量(55s)的 VAD 切分边界天然不同,强制闭段可能落句中(「…判断一个人是。/不是网红的标准…」)——v0.11 既有行为;真人说话自然闭段占主导,合成连读语音更明显。
- streaming zipformer 是 2023-02 模型,纯中文粗稿质量已够用(粗稿只求可读);换更新的流式模型是迭代项不是缺陷。
- 粗稿刷新频率 ~2.6 次/s(26.5s 里 67 次),终端渲染开销可忽略,暂不做节流。

## 迭代方向(未排期)

- **粗稿节流**:若未来换更重模型或低配机,可在 run_live 挂载点加最小刷新间隔(如 200ms),挂载点已收口在一处,好改。
- **换/加流式模型**:备选 streaming paraformer 双语(sherpa-onnx 同样支持,from_transducer 同 API);只需换 `asr_stream/` 文件与 PartialFeed 文件名,协议不动。
- **粗稿标点**:partial 加轻量标点模型收益低(粗稿行几秒内被终稿覆盖),不建议。
- **多语种粗稿**:streaming zipformer 本身双语 zh-en;ja/ko 粗稿不支持,终稿 SenseVoice --lang auto 兜底。
